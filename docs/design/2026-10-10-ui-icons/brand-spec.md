# DroidBerth — 品牌与视觉系统摘要

来源：App 图标方向 `two-berths`（两块竖长白色圆角面板 + 中间粗圆头人字箭头，暖橙渐变 #F9A04A → #DE6B20），主色 #ED8725、辅色 #1CA0AC。本文件只服务图标体系与引导插图，不重复设计 App 图标。

## 一句话

暖橙是"操作与所在位置"，青绿是"设备与连接"，其余全部交给 macOS 系统语义色；界面里出现的每一个图形都必须是 SF Symbols 或 NSWorkspace 的产物。

## 六个 OKLch token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `oklch(100% 0 0)` | 窗口/列表底（浅色）。深色 `oklch(21.4% 0.004 286)` |
| `--surface` | `oklch(98.2% 0.001 286)` | 侧栏、卡片、表头（浅色 ≈ #FAFAFC）。深色 `oklch(26.5% 0.005 286)` |
| `--fg` | `oklch(23.9% 0.004 286)` | 主文字与文件名 |
| `--muted` | `oklch(54% 0.007 284)` | 种类/大小/日期等次级列（≈ #6E6E73，5.1:1） |
| `--border` | `oklch(0% 0 0 / 0.10)` | 分隔线（深色 `oklch(100% 0 0 / 0.11)`） |
| `--accent` | `oklch(71.7% 0.160 57.9)` | 品牌橙 #ED8725，仅用于强调元素与非文字标记 |

派生色（关键）：
- `oklch(65.5% 0.164 48.5)` = #DE6B20，渐变深端
- `oklch(78.0% 0.145 61.4)` = #F9A04A，渐变浅端
- `oklch(64.6% 0.106 204.5)` = #1CA0AC，品牌辅色（连接/设备）
- `oklch(56% 0.152 55)` = **选中行填充色**。品牌原色 #ED8725 作填充时白字只有 2.6:1，不达标；此派生值把白字提到 4.9:1。

## 字体栈

- 显示/界面：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Helvetica Neue", sans-serif`
- 等宽（symbol 名、扩展名、adb 输出）：`ui-monospace, "SF Mono", SFMono-Regular, Menlo, monospace`

不做第二套显示字体：这是工具型、数据密集的界面（§8-1 也只允许系统视觉）。

## 观察到的规则

1. **形状承担类型，颜色承担来源，文字承担精度。** 图标永远不是唯一信息载体（§8-3）：种类列、大小、日期必须能脱离图标独立读懂这一行。
2. **只有两条实现路径**：`NSWorkspace`（系统彩色文件图标）与 SF Symbols（单色矢量）。不新增任何自绘位图，不自定义粗细/圆角/配色。
3. **16pt 下三秒可辨。** 两个符号若需要凑近才能分辨，就合并为一个——合并是默认答案，新增需要理由。
4. **图标不承诺运行时事实。** "这个文件手机能不能打开""这个包能不能装"由禁用态与文案回答，不由图标回答。
5. **一套符号名，两种呈现。** 同一类型在本机与设备两侧使用同一个 symbol 名，只有彩色/单色的差别。

## 硬性禁忌

- 不用品牌原色 #ED8725 作选中行或按钮填充（白字 2.6:1）。
- 不用 `tertiaryLabelColor` 作 48pt 空态图标（约 1.9:1）。
- 选中行内不使用任何降透明度的文字——选中填充上的次级灰只有 1.3:1。
