# 第一部分：PRD

## 1. 产品定位

**一句话**：插上线，把 Mac 上的视频和照片推到手机，像用 Finder 一样浏览两端。

DroidBerth 是一款 macOS 应用，让用户在 Mac 与 Android 手机之间双向传输文件，**并以「Mac → Android」为主场景优化**。ADB 二进制内嵌在 app 内，用户不需要安装 Android SDK、不需要接触终端、不需要理解 ADB。

**它不是什么**：不是设备管理器，不是开发者工具，不是备份工具。范围刻意收窄（见 §4）。

## 2. 目标用户

**主用户（唯一主用户）：摄影师 / 视频创作者**

手上有大量已拍摄、已在 Mac 上整理过的视频与照片素材，需要把它们推到 Android 手机上——用于在手机上看片、给客户/同事看、装到平板或备用机上播放。

这个选择决定三件事：
- **默认交互是「推」而不是「拉」**：窗口里最高频的动作是 Mac → Android。
- **单次传输量大**：几十到几百个文件、单个文件可能上 GB。
- **素材来源常在图库里**，不在普通文件夹里（→ §18 照片图库来源）。

**次用户**：Mac + Android 双设备用户，双向零散交换文档与照片。

**明确排除**：开发者/技术用户。ADB 终端、日志流、整机备份都不做——它们会把产品拉向另一个形态。

## 3. 用户核心场景

| 场景 | 方向 | 频率 | 备注 |
|---|---|---|---|
| **推送素材到手机** | Mac → Android | **高（主场景）** | 可能来自 Finder，也可能来自照片图库 |
| **浏览设备内容** | 只读 | 中 | 确认推送到位了没、看看手机里有什么 |
| **回传文件** | Android → Mac | 中 | 手机拍的、下载的东西拿回 Mac |
| **整理设备文件** | 删除 / 重命名 / 新建文件夹 | 中 | 「放错地方了挪一下」「传错了删掉」 |
| **从照片图库推送** | Mac 照片库 → Android | 高 | 主场景的一种来源形态 |

> v1.0 的场景表把「导入照片到 Mac」列为高频第一行，方向是反的，已修正。

| 维度 | 要求 | 依据 |
|---|---|---|

| 安全 | 全程本地传输，不经云，不收集用户数据 | — |

## 6. 技术约束

### 6.1 adb 的来源（v1.0 的前提已推翻）

v1.0 §6 与 §24 写的是「ADB sidecar 必须自行编译（AOSP Soong），不得直接分发 SDK 中的 platform-tools 二进制」。**这条建立在一条不成立的前提上。**

实测证据（`vendor/` 目录）：

| 证据 | 结果 |
|---|---|
| `vendor/adb-build/` | **空目录** |
| `vendor/platform_system_core/adb/` | **不存在**（sparse checkout 未落地；顶层只有 `libcutils`/`libutils`/`rootdir` 等） |
| 全树 `CMakeLists.txt` | **0 个** |
| 全树 `Android.bp` | **15 个**（Soong） |
| 仓库里唯一的 `adb` | SDK 的 universal 18 MB 副本，**非自建** |

`scripts/build-adb.sh` 自己的 VERDICT 写着：

> A self-built adb is a **build-glue project, not a script**.

它验证的是**这条路不通**（上游没有 CMake 路径），不是通了。三个候选第三方仓库全部陈旧（2016 / 2021 / 2024），其中两个**没有任何许可证**。

**v2 的决策**：v1 使用 **SDK 的 adb**，走 demo 已验证的路径（`scripts/use-sdk-adb.sh`）。

- 已验证依赖**全部是系统库**（`otool -L` 非系统路径依赖 0 个），不构成公证障碍。
- **必须随包附 `NOTICE.txt`。**
- 许可实情：`NOTICE.txt` 声明整包 Apache-2.0；SDK 条款的再分发禁令是 **§3.4**（v1.0 引用的 §3.3 是错的），而 **§3.5 对开源许可组件有豁免**。所以「必须自建才能公开分发」这个前提本身不成立。
- **但这仍不是法律意见。** 公开发布前必须让法务确认 §3.5 的适用性。**不要写成「无风险」。**
- 自建 adb 列为「若法务否决则切换」的备选，且必须按 **build-glue 项目** 立项（自己的周期与估算），不是脚本。

### 6.2 其它约束

- sidecar 定位用**相对自身可执行文件**的路径，不用安装路径拼接。
- 子进程封装必须**同时抽干 stdout 和 stderr**，并带超时。
- **禁止手写 `hdiutil create`**，统一走 `scripts/env.sh` 的 `make_signed_dmg()`。
- 构建前清理源目录里的 `rw.*.dmg`（`hdiutil` 自毒化，见交接文档 §2.4）。
- 不要把 `src-tauri/binaries/adb-*`（SDK 的 18 MB universal）打进产品包——体积与许可双重理由。

## 7. 开发路线图

> v1.0 的「4–6 周 MVP」是在更小的范围下给的。本次范围已显著扩大（双栏、照片图库、无线进 P0、设备端写操作），**旧估算不再可比**。改用阶段 + 退出条件描述。

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| **Phase 0 — 前置** | 代码改名到 DroidBerth（§26）；`minimumSystemVersion` 改 14.0；bundle targets 收敛为 `app` | 改名后重跑构建 + 公证 + staple，`spctl` 与 `stapler` 全绿 |
| **Phase 1 — 传输内核** | 双栏骨架；USB 检测；上传/下载；传输队列；落点分流与重名策略 | 能把 200 个文件从 Mac 推到手机，无丢失、无覆盖、进度准确 |
| **Phase 2 — 素材来源** | 照片图库来源（Photos framework + TCC 授权）；照片权限被拒时的降级路径 | 能从照片图库批量导出并推送，导出有进度且可取消 |
| **Phase 3 — 设备端操作** | 删除 / 重命名 / 新建文件夹；媒体入库兜底 | 删除有二次确认；媒体入库在**至少 3 个 Android 版本**上实测过 |
| **Phase 4 — 无线** | 静默双通道；无线状态呈现；重启后的再激活引导 | 拔线后自动续连；断开重连 3/3；手机重启后引导正确出现 |
| **Phase 5 — 发布** | universal 构建；干净 VM 复验；Sparkle 接入；法务确认 | §28 清单全绿 |

**关键路径上的未知**：媒体入库（§19）。它可能推翻 Phase 3 的一部分设计，所以**应当尽早实测**，不要留到 Phase 3。

# 第二部分：产品设计文档

## 8. 设计原则

v1.0 原则一写的是「系统组件优先于自绘 UI」。**这句话在 Tauri 里无法成立**——Tauri 用 WKWebView 渲染，侧边栏、列表、工具栏、按钮，每一个像素都是 HTML/CSS 自绘的，只是画得像。把一条做不到的原则写进文档，会导致后续每一次设计评审都失去判据。

重写为四条可执行的：

### 原则一：照 HIG 自绘，并承认这是自绘

- **不引入非系统视觉**：不用自定义圆角卡片、不用非系统配色、不用非系统字体。字体一律走系统字体栈（`-apple-system`）。
- **尺寸、间距、字号、控件形态照 HIG 的数值抄**，不自创。宁可「平庸但正确」，不要「有设计感但不对」。
- **系统能提供的一律调用系统**，不重造：红绿灯、菜单栏、右键菜单、拖拽光标与徽章、文件选择器、通知、Quick Look、系统弹窗。
- **判据**：把窗口截图和 Finder 并排放在一起，用户不应看出哪边是 Web。

### 原则二：内容层延伸至工具栏下方

使用 `titleBarStyle: "Overlay"`，WebView 内容填满窗口，原生红绿灯嵌在应用 chrome 中。左侧预留约 78px 给交通灯区域。

### 原则三：材质只用于导航层，且要承认它是近似的

工具栏、窗格头、传输面板可用材质；表格、列表、文件内容区不使用。

**已知代价（v1.0 未提）**：Tauri 的 `windowEffects` 可以给**窗口级**背景设置原生材质（macOS 走 `NSVisualEffectView`），但**页面内元素**拿不到系统材质，只能用 `backdrop-filter` 近似。这意味着自绘的窗格头**不会**在窗口失焦时自动降饱和、**不会**随「降低透明度」辅助功能设置变化。

- 具体可用的 effect 名称与在 Tauri 2.11.5 上的实际行为**未实测**，Phase 1 视觉稿阶段必须实测。
- 若实测不可行，**优先放弃材质**，改用系统色的纯色，而不是用 CSS 硬仿——仿不出来的部分比不做更伤「原生感」。

### 原则四：每个主命令有快捷键，且不覆盖系统语义

见 §22。注意：**⌘C / ⌘V 在本产品里必须被占用**（跨栏 = 传输），v1.0 把它们列为「不可占用」是错的。

**为什么是双栏而不是单栏**：主场景是「推」。双栏让「从 Mac 挑 → 拖到设备」在一次视线内完成，不需要在 Finder 和 app 之间来回切窗口。这也是 macOS 上双栏文件管理器的既有约定（ForkLift / Commander One / Path Finder）。

**代价（必须承认）**：每个窗格都要有完整的列表 / 分栏 / 网格三种视图，UI 工作量相对单栏翻倍。

## 10. 窗口与工具栏

| 位置 | 控件 | 说明 |
|---|---|---|
| 工具栏左 | 视图切换（列表 / 分栏 / 网格） | 分段控件，作用于**当前聚焦窗格** |
| 工具栏中 | 交换两侧（⇄） | 把两个窗格的当前位置互换 |
| 工具栏右 | 搜索框 | 作用于当前聚焦窗格 |

## 14. 传输面板

跨两栏宽度，位于窗口底部。无任务时隐藏，有任务时自动展开，可手动固定。

- 每行一个任务：方向图标（⬆ / ⬇）、文件名、进度条、速度、剩余时间、取消按钮（hover 时显示）
- 折叠态为单行摘要：「3 个传输中 · 2 个等待 · 1 个失败」
- **不用模态对话框展示进度**——传输必须非阻塞
- 失败任务整行用系统警示色标出，并提供「重试」与「查看原因」

## 15. 传输默认约定

这三条是最常被踩的默认值，必须明确。

### 15.1 落点分流（设备窗格当前目录不是目标时）

| 文件类型 | 默认目标 |
|---|---|
| 视频（mp4 / mov / mkv / avi / webm） | `Movies/` |
| 图片（jpg / png / heic / gif / webp / raw） | `DCIM/` |
| 其它 | `Download/` |

**设置里可改**，也可整体关掉改为「一律落到当前目录」。

> 说明：`DCIM` 语义上是「相机」目录，把用户导入的图片放进去略有语义偏差；但它是相册扫描最稳的目录。若实测发现 `Pictures/` 同样能被相册正确索引，应改为 `Pictures/`。

### 15.2 记住上次

按**设备序列号**记住该设备上次用过的目标目录。**优先级高于分流规则**——用户上次明确去过哪，下次默认还去那。

### 15.3 重名冲突

- **默认：保留两者**，自动加 ` (1)`、` (2)` 后缀。与 Finder 行为一致。
- **绝不静默覆盖。**
- **传输前批量预检**：开始前一次性列出目标目录内容，把所有冲突判定完，而不是传到一半才发现。冲突数量 > 5 时在传输面板上给一条汇总提示（「其中 12 个文件已存在，将保留两者」）。

## 16. 设备端写操作

| 操作 | 行为 | 保护 |
|---|---|---|
| 新建文件夹 | 设备端 `mkdir` | 重名时提示，不静默改名 |
| 重命名 | 设备端 `mv` | 重名时提示 |
| 删除 | 设备端 `rm` | **二次确认**，文案必须明确「此操作不可撤销」；多选时列出文件数与总大小 |

**为什么删除不做回收站**：设备端没有标准回收站；自己建隐藏目录会污染用户设备、且用户拔线后看不见它。v1 用「二次确认 + 明确文案」，把「设备端回收站」列为 P2 候选。

**待验证**：设备端文件名的合法字符集。`/sdcard` 通常是 FUSE 层，底层 ext4/f2fs 允许大多数字符，但 MediaStore 可能不索引某些字符，FAT32 格式的 SD 卡则明确禁止 `: * ? " < > |`。重命名校验规则需要实测后确定。

## 17. 连接与引导

### 17.1 USB（默认通道）

- 插入后轮询 `adb devices -l`：活跃时 1 秒间隔，空闲 5 秒后退避到 3 秒
- **未授权**（`unauthorized`）时显示引导卡片：手机上的「允许 USB 调试？」图示 + 「勾选『始终允许』再点确定」+ 「已完成，重新检测」按钮
- **厂商差异**：小米 / OPPO / vivo 的开发者选项流程含额外风险提示与等待步骤，引导卡片按检测到的品牌显示对应图文

### 17.2 无线（静默双通道，P0）

**核心原则：用户不应该看见「连接方式」这个概念，只应该看见「设备在不在」。**

- 按设备序列号记住上次的 `IP:5555`
- USB 在线时**一律走 USB**（更快）
- USB 拔出后**自动尝试** `adb connect <ip>:5555`，**失败不弹错误**
- 失败时只在设备卡片上显示一个**可点的状态点**（灰点 + 「无线未连接」），点开才展开原因
- 无线连接成功后，设备窗格头显示 Wi-Fi 图标

**首次启用无线的引导**（需要 USB 激活一次）：
1. 设备已通过 USB 连接
2. 用户在 Device 菜单选「启用无线连接」
3. 执行 `adb tcpip 5555`
4. 读取设备 IP（`adb shell ip addr show wlan0`）
5. 提示可以拔线
6. 执行 `adb connect <ip>:5555`

**已知限制，必须做成引导而不是报错**：手机重启后端口失效，需要重新插线激活一次。检测到「记住的无线设备连不上且当前无 USB」时，显示「需要插线重新激活一次」的引导卡片。

**5037 端口冲突**：启动时检测四种状态（空闲 / 是我们自己的 adb / 是别的 adb / 是非 adb 进程，判定方法见交接文档 §1.5）。是「别的 adb」时提示用户——版本不一致会静默改变行为。

## 18. 素材来源：Finder + 照片图库

主用户的素材常常在照片图库里，不在普通文件夹里。

### 18.1 技术约束（实测结论）

- 第三方 app **不能直读**照片图库。必须走 Photos framework，并在「系统设置 > 隐私与安全性 > 照片」里获得授权。
- **没有任何免授权路径。**
- 需要在 Info.plist 里提供 `NSPhotoLibraryUsageDescription`。
- 导出是**异步**的（`requestExportSession` / `requestImageData`），必须有进度与取消。

### 18.2 设计

- Mac 窗格头的「来源」下拉可切到「照片图库」
- 浏览维度：相册 / 时间（年-月-日）/ 媒体类型（照片 / 视频）
- 选中后拖到设备窗格 = 先导出到临时目录再推送。**UI 上必须把「导出」和「推送」两段进度分开显示**，否则用户会以为卡住了
- 权限被拒时的降级路径：显示一条可点的提示「去系统设置开启照片访问」，同时**产品其余功能完全不受影响**（不能因为照片权限被拒就挡住普通文件传输）

## 19. 媒体入库（MediaStore）—— 最高风险项

### 19.1 问题

`adb push` 是把文件写到文件系统，**不经过 MediaStore**。而 Android 的相册 / 图库读的是 MediaStore 索引，不是文件系统的实时视图。**如果索引不更新，用户推过去的文件在相册里看不见——产品在核心任务上就失败了。**

### 19.2 证据状态（不要写成「已知缺陷」）

| 结论 | 强度 |
|---|---|
| `MEDIA_SCANNER_SCAN_FILE` 广播在 **API 29 已废弃**（官方原文：应改为直接插入 MediaStore，插入后自动扫描） | **已确证** |
| Android 11+ 起 MediaProvider 走 FUSE，AOSP 表述为「文件系统与数据库保持一致」 | 已确证，但**未明确 `adb push` 这个场景** |
| 因此 11+ 上可能**自动入库**，旧版本上很可能**看不到** | **推断** —— 必须真机逐版本实测 |
| 没有任何来源能确认某条扫描命令在 **Android 10–16 全版本**有效 | **未查到** |

### 19.3 v1 策略

1. **以新 API 为基准**：优先使用 MediaStore 的插入/扫描路径，而不是已废弃的广播。
2. **按 Android 版本选择命令**，并在传输完成后对每个已传文件触发一次扫描。
3. **全部命令标为待验证**，并在**至少 3 个 Android 版本**（建议 10 / 13 / 15）上实测。
4. **兜底引导**：扫描失败时，在传输完成卡片上给一条明确、可操作、不甩锅的指引——「在手机上打开相册，下拉刷新；若仍看不到，重启手机后即可出现」。
5. **不要静默失败。** 媒体入库失败必须在 UI 上可见，否则用户会在几小时后才发现相册是空的，而那时已经找不到原因。

### 19.4 如果实测证明全版本都无法可靠入库

那说明「内嵌 adb + 零安装」这条技术路线与「推送后立刻能在相册看到」这个产品承诺**存在根本冲突**。届时需要在三件事之间做取舍：配一个 Android companion app / 改用 MediaStore API 通道 / 修改产品承诺的措辞。**这个取舍留到实测之后做，现在不预判。**

## 20. 大文件与中断代价

**`adb push` 不支持断点续传**（`SYNC_CMD_WRITE` 无 offset；中断即清理临时文件、必须全量重传）。这条的置信度为**中等**（来源非官方），但设计上按「成立」处理。

| 措施 | 说明 |
|---|---|
| 传输前检查目标分区剩余空间 | `adb shell df`，空间不足直接拒绝开始，不留到传一半才失败 |
| 大文件（> 1 GB）排在队首并**独占通道** | 减少被小文件插队导致的资源争抢 |
| 进度显示「已传 / 总量」的绝对数值 | 不能只给百分比 |
| 失败时明确告知重传代价 | 「已传输 6.2 GB，重试将从 0 开始」——不能让用户以为会续传 |
| 一键重试 | 保留原目标路径与重名策略 |

**不做分片续传**（绕过 `adb push` 用 `adb shell` + dd 逐块写）。理由：要自己实现校验与进度记账，且会明显拖慢速度，收益不足以进 v1。

## 21. 外观与深色模式

- 三档：Light / Dark / Match System，默认 Match System
- **实现约束（来自验证经验）**：macOS 上 `preferredColorScheme(nil)` **不会**清除之前强制设置的窗口外观。用户从 Dark 切回 Match System 时，窗口会卡在 `darkAqua`。正确做法是通过 `NSApplication.shared.appearance` 驱动，`nil` 表示跟随系统。
- 在 Tauri 里这意味着外观控制必须在 Rust 侧设置 `NSApp.appearance`，**不能只靠前端 CSS**。
- 材质限制见 §8 原则三。

### ⌘C / ⌘V 的正确语义（修正 v1.0）

v1.0 把 ⌘C / ⌘V 列为「保留给文本和列表的默认行为，不覆盖」。**这在文件管理器里是错的。**

在 Finder 里，选中文件后 ⌘C、切到另一个窗口 ⌘V，就是拷贝文件。双栏文件管理器里，这个动作的自然含义就是**跨栏传输**：

- Mac 栏选中 → ⌘C → 设备栏 ⌘V = **上传**
- 设备栏选中 → ⌘C → Mac 栏 ⌘V = **下载**
- 同栏内 ⌘C → ⌘V = 在同一侧复制（设备侧走 `cp`；Mac 侧走 Finder 的拷贝语义）

**例外**：焦点在文本输入框（重命名、新建文件夹、搜索）时，⌘C / ⌘V 恢复为文本编辑语义。这是标准的 responder chain 行为，必须正确处理。

### 不覆盖的系统快捷键

⌘Z / ⇧⌘Z（撤销）、⌘A、⌘F（搜索聚焦）、⌘W、⌘Q、⌘H、⌃⌘F。

**关于撤销**：设备端文件系统操作（删除 / 重命名 / 移动）**不可撤销**——设备端没有回收站。⌘Z 仅作用于文本输入。这必须在删除确认文案里说清楚，不能给用户「反正能撤销」的错觉。

## 23. Quick Look

### 目标形态

按空格键，**就地**弹出 Quick Look 面板预览选中的文件。

### 现实约束

- Tauri 官方不支持 Quick Look，需 `tauri-plugin-quicklook` 包装 `QLPreviewPanel`
- **`QLPreviewPanel` 是系统预览面板，不是独立窗口**——v1.0 用 `qlmanage -p` 是**另开一个预览窗口**，与 Finder 的空格预览体验不同，属于降级方案
- 预览需要本地文件，所以流程是：选中 → 拉取到 `$TMPDIR/DroidBerth/preview/` → 预览 → 关闭后清理

### 策略

1. **优先**：接 `QLPreviewPanel`，做到就地预览
2. **降级**：若插件不可用或行为不符，用 `qlmanage -p`，并在文档与 UI 上如实说明这是「打开预览窗口」而非就地预览
3. **优化**：图片只拉文件头生成缩略图；只有用户真的按空格才拉完整文件
4. **大文件保护**：> 200 MB 的文件按空格时先确认（「该文件 4.2 GB，预览需要先下载到本机」），不要静默开始下载

## 24. 拖拽

遵循 macOS 约定：**同一容器内拖拽 = 移动；跨容器拖拽 = 拷贝**。

| 拖拽方向 | 行为 |
|---|---|
| Finder → 窗口（任意位置） | 上传到设备窗格当前目录 |
| Mac 窗格 → 设备窗格 | 上传 |
| 设备窗格 → Mac 窗格 | 下载 |
| 设备窗格 → Finder | 下载到 Finder 目标位置 |
| 设备窗格内部 | 设备端移动（`mv`） |
| 设备 A 窗格 → 设备 B 窗格（P1） | 经 Mac 中转 |

- 拖拽进入目标区域时高亮
- 释放后任务进入传输面板，**不弹任何对话框**
- 拖拽多选时显示文件数量徽章
- **不可拖拽的情况要有明确反馈**：`Android/data`、`Android/obb` 不可写入，拖上去应显示禁止光标而不是静默失败

## 25. 无障碍

| 维度 | 要求 |
|---|---|
| VoiceOver | 每个列表行有完整 accessibility label（文件名 + 种类 + 大小 + 日期 + 所在窗格） |
| 全键盘导航 | Tab 在「Mac 窗格 → 设备窗格 → 传输面板」循环；方向键在列表内导航；⌘⌥← / ⌘⌥→ 在窗格间切换 |
| 对比度 | 所有文本满足 WCAG AA（4.5:1） |
| Reduce Motion | 传输进度条动画退化为静态更新 |
| 动态字体 | 支持系统「辅助功能 > 显示 > 文字大小」 |
