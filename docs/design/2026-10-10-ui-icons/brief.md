## Run 1 · App 图标

| 项 | 值 |

| 目标产物 | `app-icon-directions.html` |

**prompt 要点（原文见 run 事件流）**

- 产品：macOS 双栏文件管理器，主场景 Mac → Android 推送视频/照片；名字里的 Berth 是「泊位」
- 硬约束：① 视觉必须原生（与 Finder / 访达 / Safari 并排不显外来）；② 不放文字 / 字母缩写 / 水印；③ 必须能缩到 16×16 pt 仍可辨认主形；④ **几何必须清晰、可用代码复现**（最终会用纯几何 + 单层线性渐变重新写成零依赖渲染脚本 ⇒ 禁止照片纹理、复杂多层高光、噪点、3D 渲染感）
- macOS 规范：1024 画布 / 824 内容区居中 / 四周 100pt 留白 / 超矩形圆角 ≈185.4pt（continuous corner）/ 自带 Apple 量级投影
- 要求产出：3 个方向（A 双栏+渡口 / B 传输带 / C 泊位端口），每个含 1024 母版 + 尺寸阶梯（1024/256/128/64/32/16）+ Dock 上下文（浅色与深色）+ ≤3 条取舍说明；最后给推荐方向、品牌强调色（主色 + 辅色 hex，含浅深模式表现）、一句话命名

## Run 2 · 图标体系与引导插图

| 项 | 值 |
|---|---|
| 项目 | `droidberth-icons` |
| runId | `57418b81-2a9d-4570-b74d-1665434e1d4d` |
| requestId | `02FA4DBB-3E1C-4669-B592-E9F3E7CDE856` |
| 目标产物 | `icon-system.html` |

**prompt 要点**

- 实现面约束（决定性）：图标最终**只能**落到两类 —— SF Symbols（单色矢量）或 `NSWorkspace` 返回的系统文件图标。**不要设计自绘位图图标集**；每个图标都要标注走哪条路、候选 SF Symbol 名
- 原则约束（PRD §8）：优先系统控件与系统图标；中文界面；图标不得作为唯一信息载体
- 四块内容：
  1. **文件类型图标体系** —— 36 类扩展名的完整对照表（类型 / 扩展名 / 图标 / 实现路径），16pt 实际尺寸渲染；并给出「必须新增映射」的结论清单（哪些值得单独给符号、哪些不值得，理由要具体）
  2. **两栏来源区分策略** —— 甲（都用系统彩色图标）/ 乙（本地彩色 + 设备单色）/ 丙（都用 SF Symbol）三选一，各配「两栏并排各三条目」小样 + 直白判断
  3. **USB 授权引导卡片**（PRD §17.1）—— 手机授权弹窗示意图（CSS 画）+ 三步说明 + 「已完成，重新检测」按钮 + 品牌文案槽位；按 300pt 宽设计（要嵌进 340pt 窗格），浅色与深色两版
  4. **四类空态** —— 未连接设备 / 照片权限被拒 / 文件夹为空 / 搜索无结果；每类 icon（标注 SF Symbol 名）+ 主文案 + 辅助文案 + 可选按钮
- 末尾要求一张「结论清单」，便于直接抄进代码
