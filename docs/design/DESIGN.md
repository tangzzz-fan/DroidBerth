## 1. 品牌色，以及它**不**进界面

| 角色 | Hex | OKLCH | 深色底 | 浅色底 | 用在哪 |
|---|---|---|---|---|---|
| 品牌主色 | `#ED8725` | `oklch(0.72 0.16 58)` | 6.6:1 ✅ | 2.6:1 ❌ | **只在 App 图标里** |
| 品牌辅色 | `#1CA0AC` | `oklch(0.645 0.105 205)` | 5.4:1 ✅ | 4.6:1 ✅ | 传输方向标识的「下载」 |
| 图标渐变浅端 | `#F9A04A` | — | — | — | App 图标底板 |
| 图标渐变深端 | `#DE6B20` | — | — | — | App 图标底板 |

### 为什么主色不进界面（这条是**主动否决稿子建议**的结果）

设计稿建议把 `#ED8725` 同时用在 App 图标与界面里的方向标识上。**没有采纳**，理由是它与 app 现有的**警示色撞车**：

| 现有用途 | 颜色 |
|---|---|
| `MainView` 的 banner 警告级 | `.orange` |
| `TransferPanel` 的「媒体入库失败」 | `.orange` |
| `PhotoSourceView` 的「仅部分照片可访问」条 | `.orange` |

把品牌主色定成暖橙，等于让**「正常的主要动作」与「出事了」共用一个色相**。在传输工具里代价很具体：传输面板上橙色会同时意味着「上传中」和「入库失败」。

所以分成两条规则：

1. **图标用暖橙。** Dock / Finder / About / DMG 里它是辨识度，与界面内的语义色不冲突。
2. **界面里的方向标识继续用系统语义色**：上传 = `Color.accentColor`（跟随用户的强调色设置 —— PRD §8「不引入非系统视觉」），下载 = 定名的品牌辅色 `Color.brandSecondary`。

> 顺带修掉一个既有缺陷：改造前下载用的是 `Color.teal` —— 一个系统调色板里的固定色板项，**不跟随强调色**，而「为什么下载是 teal」没有答案。现在它有名字、有理由、有唯一的定义处。

## 2. 语义色映射

| 用途 | 值 | 对比度判据 | 落点 |
|---|---|---|---|
| 窗口 / 列表底、主文字、分隔线 | 系统语义色 | — | 全局 |
| **数据列文字**（种类 / 大小 / 修改日期） | 浅 `#6E6E73`　深 `rgba(235,235,245,.62)` | 浅 **5.1:1** / 深 **6.3:1** | `Color.columnText` |
| 上传方向标识 | `Color.accentColor` | 跟随系统 | `TransferDirectionTint` |
| 下载方向标识 | `#1CA0AC` | 浅 4.6:1 ✅ | `TransferDirectionTint` |
| 聚焦窗格 | 系统色 2pt 描边 + 6% 底 + 标题加重 | 形状 + 字重双通道，不只靠颜色（PRD §25） | `PaneFocusStyle` |
| 拖拽落点高亮 | 系统色 3pt 描边 + 12% 底 | 同上 | `PaneDropHighlight` |
| 失败行 | `Color.red`（底 7%） | — | `TransferPanel` |

**唯一一处对系统默认的有意偏离**：数据列文字**不用** `secondaryLabelColor`。

理由不是审美：`secondaryLabelColor` 在浅色模式下对白底只有 **3.95:1**，低于 PRD §25 明文要求的 WCAG AA 正文 4.5:1。这是一次**被 PRD 要求**的偏离。它只用在承载数据的那几处，纯装饰元素（面包屑分隔符、路径栏图标）继续用系统语义色 —— 不然整条视觉层级会被抹平。

## 3. 图标体系

### 3.1 两条路径，各管一栏

| 栏 | 路径 | 为什么 |
|---|---|---|
| 左（这台 Mac） | `NSWorkspace.shared.icon(forFile:)`，按 `path` 缓存 | 文件**真实存在** ⇒ 零维护地拿到 Finder 的观感，顺带白拿替身角标、全部办公文档类型、App 包图标 |
| 右（设备） | 自建的「**完整扩展名**精确匹配 → SF Symbol」表 | 条目只是 `adb shell ls` 列出的一行，本机**没有对应文件**，问 `NSWorkspace` 只能拿到笼统的通用图标 |
| 照片图库 | `isVideo ? "film" : "photo"` | 媒体类型是 PhotoKit **权威给出的**，比从文件名猜扩展名更准（文件名可能没有扩展名） |

**被否决的「两栏都用系统彩色图标」**：它在设备侧会**稳定谎报** —— `base.aab` 这类 Android 专有扩展名在右栏只能回退成灰色的通用文稿图标，而它混在一排彩色图标里看起来仍像「系统认识它」。

**只有一条分支依据**：`BrowserEntry.origin`。颜色承担来源，形状承担类型，文字承担精度（PRD §8-3：图标永远不是唯一信息载体）。

### 3.2 新增一个符号的判据

一个类型值得拥有独立符号，**当且仅当三条同时成立**：

1. 用户会对它做出**不同的动作**（dmg 是挂载，zip 是解压）；
2. 它在目标用户（会用 adb 的摄影师 / 视频创作者）的文件里**高频**；
3. **SF Symbols 里有一个现成的、16pt 下与已有符号可辨的符号。**

第 3 条最常被忽略：**不过就合并，不要为了凑一个图标去自绘。**

### 3.3 符号表

完整表在 `Support/FileTypeIcon.swift` 的 `symbolByExtension`（当前 **77 个扩展名**）。归类原则：

| 符号 | 覆盖 | 备注 |
|---|---|---|
| `folder.fill` | 目录 | 目录优先于扩展名（叫 `foo.txt` 的文件夹仍是文件夹） |
| `photo` | jpg jpeg png heic heif gif webp tif tiff bmp avif svg dng raw cr2 nef arw | **全部图片格式共用一个** |
| `film` | mp4 mov m4v mkv avi webm wmv flv 3gp **ts** | `ts` = MPEG 传输流，与 macOS 自身的关联一致 |
| `waveform` | mp3 wav aac flac m4a ogg opus wma | 改造前是 `music.note`（一个音符）—— 换掉是有意的 |
| `doc.richtext` | pdf rtf | |
| `tablecells` | xls xlsx csv numbers | **新增** |
| `doc.text` | txt md log doc docx pages ppt pptx key | 演示文稿刻意并入 |
| `doc.zipper` | zip rar 7z tar gz bz2 xz | |
| `opticaldisc` | dmg iso | **新增** |
| `shippingbox` | apk aab ipa exe | **不要用图标表达「这个不能推到 Android」**，那是禁用态与文案的职责 |
| `chevron.left.forwardslash.chevron.right` | json xml yaml yml toml plist sh py js tsx swift rs html css | **新增** |
| `doc` | 无扩展名 / 未知 | 靠「种类」列区分「无扩展名」与「未知」 |

**刻意不新增的（合并是默认答案）**：heic 与 jpg 分图标是纯噪声；RAW 不单独给符号（**能不能开是运行时才知道的事，该由文案回答，不该由图标承诺**）；全部视频 / 音频容器合并；`aab / ipa / exe` 并入 `shippingbox`。

### 3.4 已核对（2026-10-11，本机实测）

用 `NSImage(systemSymbolName:accessibilityDescription:)` 逐个探测，**69 个在本项目里用到的符号全部存在**，其中包含设计稿标为「把握较低、建议核对」的 `tablecells` / `opticaldisc` / `cable.connector` / `arrow.turn.up.right`。

最低版本要求：`tablecells` 与 `chevron.left.forwardslash.chevron.right` 需要 SF Symbols 4（macOS 13+），本项目最低 macOS 14 ✅。

### 3.5 已知冲突

| 冲突 | 取舍 |
|---|---|
| `ts`：MPEG 传输流 vs TypeScript | **按视频归类**，与 macOS 自身关联一致。不加「同目录有 package.json 就判代码」这种启发式 |
| `key`：Keynote 文稿 vs 私钥 | 都进 `doc.text`；私钥通常带 `.pem` 或没有扩展名 |
| 扩展名必须**完整精确匹配** | 不能截前缀 —— 否则 `m4a` 被 `m4` 吞掉、`tsx` 被 `ts` 吞掉 |

## 5. 空态与设备引导

### 5.1 结构

空态**不是**一个字符串，而是 `PaneEmptyState`（图标 + 主文案 + 辅助文案 + 可选主按钮 + 可选文字链 + 可选排查清单 + 可选引导卡片）。改造前它是字符串，直接导致两个后果：四类语义不同的空态共用一个 `tray` 图标，且**一个按钮都挂不上**。

### 5.2 四类常规空态

| 场景 | 符号 | 主文案 | 动作 |
|---|---|---|---|
| 文件夹是空的 | `folder` | 这个文件夹是空的 | **无按钮**（中性状态，不是错误） |
| 搜索无结果 | `magnifyingglass` | 没有找到与「{关键词}」匹配的文件 | 「清除搜索词」 |
| 本地读不到目录 | `exclamationmark.triangle` | 打不开这个位置 | 「重试」 |
| 照片图库权限被拒 | `lock` | DroidBerth 没有照片访问权限 | 「打开系统设置」+「先用 Finder 位置」 |

### 5.3 三类设备指引

| 场景 | 触发条件 | 版式 |
|---|---|---|
| 未连接任何设备 | `status == .idle` 且无设备 | `cable.connector` 空态 +「重新检测」+「连接不上？」popover |
| **未授权**（PRD §17.1） | 存在 `state == .unauthorized` 的设备 | **引导卡片**：手机授权弹窗示意图 + 三步 + 「已完成，重新检测」+ 品牌文案 |
| **无线需重新激活**（PRD §17.2） | 无在线设备且存在已记住的无线设备 | 引导卡片（插线示意图版） |

### 5.4 四条落地规则（对错可判）

1. 主文案要**带上产生空态的那个具体值**（「没有找到与『合同』匹配的文件」比「无搜索结果」多给一条确认信息）。
2. 空文件夹**不用任何警示色或感叹号**，也不该有主按钮 —— 把中性状态做成操作入口会让人以为出了问题。
3. 照片权限那条**必须写明「其余功能不受影响」** —— 权限被拒最坏的后果不是少了照片，而是用户以为整个 app 废了。因此次级按钮不是「稍后再说」这种什么都不做的措辞，而是「先用 Finder 位置」，**真的把人带到还在工作的那一侧**。
4. 搜索空态的按钮**始终只有一个**，但它清除的正是用户当前的阻碍。

### 5.5 品牌文案（PRD §17.1「厂商差异」）

`AndroidDevice.brandFamily` 从 `adb devices -l` **已经带回来的** `model` / `product` / `device` 字段推断（小米 / OPPO / vivo / 三星 / 华为）。

**为什么不用 `getprop ro.product.brand`**：需要这张卡片的时候设备往往正是「未授权」，而**未授权状态下 `adb shell` 跑不了** —— 最权威的那条路恰恰在关键时刻不可用。文案一律写成「还可能需要…」而不是断言：这些额外步骤来自各家公开文档，**未在真机上逐机型核对**。

## 6. App 图标

### 6.1 几何契约（方向 `two-berths`）

| 元素 | 值 |
|---|---|
| 画布 | 1024 × 1024 |
| 内容区 | 824 × 824 居中，四周 **100pt 透明留白**（实测系统图标：`alpha ≥ 250` 的实体 bbox 是 816×816、边距 104 —— 差的 8px 是边缘抗锯齿） |
| 底板 | 超椭圆 `\|x\|⁵ + \|y\|⁵ = 412⁵`，**不是**圆角矩形 |
| 底板填充 | 垂直线性渐变 `#F9A04A → #DE6B20`，铺满**内容区** |
| 左 / 右栏 | 圆角矩形 `(158,272)-(348,752)` / `(676,272)-(866,752)`，圆角 56，白 |
| 箭头 | 折线 `(453,402)→(571,512)→(453,622)`，线宽 86，圆头圆角，白 |

**为什么是超椭圆**：稿子用 n=5 逼近 Apple 的 continuous corner —— 45° 处离角点 53.3px，而 r=185.4 的普通圆角是 54.3px。切口对得上，肩部更接近连续曲率；用普通圆角会让图标在 Dock 里显得比邻居「方」。

### 6.2 投影（实测拟合，不是拍脑袋）

| 参数 | 值 |
|---|---|
| 峰值 alpha | 0.18 |
| 向下偏移 | 8.5（master 单位） |
| 高斯半径 σ | 15.0 |
| 剖面 | **正态 CDF**，不是高斯本身 |

**依据**：把系统内置的 `Notes.app/Contents/Resources/AppIcon.icns` 解出来，量它内容区外四向的 alpha 剖面（下缘最强、上缘最弱，即向下偏移），再用「偏移 + 高斯模糊」做最小二乘。拟合结果在 40 个采样点上的残差平方和是 **24**（均方误差约 0.77/255）。

**投影是烘焙进图里的** —— 这是实测结论，不是猜的：内容区外确实有一圈非零 alpha。

⚠️ 用 `exp(-q²/2)` 会得到一个**假的平顶**（真实剖面在边缘就已经开始衰减），必须用 `Φ(z)`。

### 6.3 尺寸档位与生成方式

| 档位 | 生成方式 | 为什么 |
|---|---|---|
| 1024 | 原生渲染（4×4 超采样 + 距离场快路径） | 母版 |
| 512 / 256 / 128 / 64 / 32（32pt 档） | 自研 **2×2 面积平均**逐级折半 | 见下 |
| **16 / 16@2x(32px)** | **原生渲染，另一份几何** | 见下 |

**为什么不用 `sips -z` 降采样**：实测它会把投影压掉约 **25%**（母版下缘峰值 30/255 → 降到 256 后只剩 24），而系统图标在 256 档是 35。降采样是纯算术，自己做既准又可复现，顺带少一个外部依赖。面积平均**必须在预乘 alpha 空间里做** —— 不然低 alpha 像素里那个「黑色」会渗进邻居，图标外缘浮出一圈灰边。

**为什么 16pt 档要单独一份几何**：标准几何在 16px 下栏宽只剩约 3px、间隙不到 1px，降采样后间隙会被抗锯齿填平，整块糊成一个白团。这一档因此把栏加宽、间隙拉到 1.1px 以上、箭头换成实心三角 —— 让「两栏 + 向前推」的三段式在 16px 下仍然读得出来。

> ⚠️ 注意 `icon_16x16@2x.png` 是 **32px 的图**，但它属于 **16pt 这一档**：Retina 用户在 Finder 列表里看到的就是它，必须与 `icon_16x16.png` 共用同一份几何。而 `icon_32x32.png` 同样是 32px、却属于 **32pt** 档，用标准几何 —— 两张 32px 的图内容不同，是正常的。

**这一段与稿子的字面指示相反，是有意的。** 稿子写「把间隙压到 0、箭头并进左侧面板做成实心楔形」，照做的结果是三块并成**一片连续的白**，16px 下只剩一个白团 —— 那正是稿子自己反对 B 方向时用的失败判据。所以改成反向操作。

### 6.4 判据

```bash
python3 scripts/make-icon.py macos/Resources   # 幂等，约 50 秒
iconutil -c iconset macos/Resources/icon.icns -o /tmp/verify.iconset   # 10 档齐全
```

| 判据 | 期望 |
|---|---|
| iconset | 10 个文件齐全（16 / 16@2x / 32 / 32@2x / 128 / 128@2x / 256 / 256@2x / 512 / 512@2x） |
| 实体 bbox（256 档） | `alpha ≥ 250` 的部分 204–206 px |
| 投影剖面（256 档，下缘） | 峰值 31/255（系统图标是 35） |
| `CFBundleIconFile` | = `icon` |
| bundle 内的路径 | `DroidBerth.app/Contents/Resources/icon.icns` |

**图标入库**（2026-10-11 起）。原先不入库，理由是「可从 `scripts/make-icon.py` 完整复现，不必把二进制塞进仓库」—— **那个理由被实测推翻了**：`project.yml` 把 `Resources/icon.icns` 列成了 source，而 xcodegen 要求该路径**存在**，于是新克隆的仓库**连 `xcodegen generate` 都跑不过**（`has a missing source directory`）。它因此不是「构建产物」而是**必需的源文件**。生成仍是确定性的（同一脚本两次产出的字节完全相同，实测），`build.sh` 也只在脚本比产物新时才重跑（原生渲染一张 1024 母版约 50 秒）。

**尺寸对比图**：`docs/design/2026-10-10-ui-icons/app-icon-contact-sheet.png` ——
深色底 / 浅色底各一行，从左到右是 **16 / 32（16pt 档 @2x）/ 64（32pt 档 @2x）/ 128 / 256**，
按真实像素尺寸并排。看图能看到设计意图：64 及以上是**人字箭头**，32 及以下是 16pt 档的**实心三角**。

⚠️ `icon.icns` 必须在 `xcodegen generate` **之前**生成 —— xcodegen 要求 `project.yml` 里列出的路径存在。`scripts/build.sh` 的 `==> 1/4` 就是这个步骤，且只在脚本比产物新时才重跑（原生渲染一张 1024 母版约 50 秒）。

## 7. 刻意不做 / 已否决

| 项 | 理由 |
|---|---|
| 品牌主色用在界面上 | 与警示色 `.orange` 撞车（§1） |
| 自绘图标集 / 位图资产 | PRD §8 原则一；且无法维护 |
| 选中行改用品牌色填充 | `Table` 的行选中由系统绘制、改不了；只改网格会造成「列表与网格两套选中视觉」。诊断接受（品牌原色作填充底时白字只有 2.6:1），**药方不采纳** |
| `heic` / `jpg` 分不同图标 | 用户心智里是同一件事 |
| RAW 单独给符号 | 能不能开是运行时的事，该由文案回答 |
| 用图标表达「不能推到 Android」 | 那是禁用态与文案的职责 |
| 2× 图标的「更大字形」补偿 | macOS 的 2x 表示与 1x 是同一个逻辑尺寸、同一份几何，不做尺寸相关的手工微调 |
| 菜单栏常驻图标 / DMG 背景图 | PRD §27 列 P2 |
| VoiceOver 标签 | 用户 2026-10-10 明确要求跳过 |
| 全量 `.secondary` → AA 达标扫一遍 | 会把整条视觉层级抹平（`1009_01` §4.8）。本轮只处理**承载数据**的那几处 |
