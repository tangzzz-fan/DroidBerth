# DroidBerth UI/UX 改造分阶段方案

| 项 | 值 |
|---|---|
| 版本 | v1.0（草案） |
| 日期 | 2026-10-09 |
| 范围 | `macos/` Swift 原生外壳的交互层与视觉层 |
| 前置 | PRD v2.0（`docs/0926_01_PRD.md`） |
| 依据 | 现有代码审阅（36 个 Swift 文件 / 4578 行）+ PRD §8–§25 |

---

## 0. 结论与判断

**问题不在「视觉过时」，而在交互层缺失。**

PRD §10–§25 定义了一整套 Finder 级交互（拖拽、跨栏传输、三种视图、Quick Look、全键盘导航），但 MVP 只落地了「列表 + 右键菜单 + 深色模式」三块。当前形态更接近**一个能传文件的表格页**，而不是文件管理器。

同时，**PRD 自身的 UX 章节当时也已过时**：它写于 2026-09-26，其**实现约束**停留在抽象口号与 Web 渲染的假设上，落不到 SwiftUI 的控件层，成为失效判据。

因此改造顺序必须是：**先修 PRD（Phase 0）→ 再修 UX（Phase 1+）**。若不先修，后续每次交互评审都会拿错尺子。

---

## 1. Phase 0：PRD UX 章节对齐 Swift 原生（前置，必须先做）

### 1.1 为什么必须前置

PRD 的产品意图（双栏、拖拽、⌘C/⌘V 跨栏、三视图）**全部仍然有效**，不需要推翻。
需要改的是**实现约束**——它们描述的是抽象的渲染能力边界，落不到 SwiftUI / AppKit 的真实控件上，继续留在文档里会误导实现者。

### 1.2 精确改动清单

| PRD 章节 | 现内容 | 问题 | 改法 |
|---|---|---|---|
| §8 原则一 | 「照 HIG 自绘，并承认这是自绘」 | SwiftUI 系统控件本就是原生的，无需自绘 | 改为「优先系统控件（SwiftUI / AppKit），不自造系统已有之物」 |
| §8 原则二 | 「自绘标题栏 + 78px 交通灯预留区」 | 与系统窗口装饰冲突 | 删除。SwiftUI 走 `.toolbar` + `ToolbarItem`（`.windowStyle(.hiddenTitleBar)` 按需） |
| §8 原则三 | 材质只能用 `backdrop-filter` 近似，且「不做比硬仿好」 | 前提消失：SwiftUI 有原生 `.regularMaterial` / `.bar` | 改为「材质用原生 Material API；导航层可用，内容区不用」 |
| §10 窗口与工具栏 | 同 §8，含交通灯预留区 | 同上 | 重写为 `NSToolbar` / SwiftUI `toolbar` 布局，保留控件清单 |
| §21 外观 | 「外观必须由底层（非 UI 层）驱动 `NSApp.appearance`」 | 结论正确、措辞过时（`AppearanceController` 已实现） | 保留结论，更新为「经 `NSApplication.shared.appearance` 驱动」 |
| §23 Quick Look | 「插件包装 `QLPreviewPanel`，`qlmanage -p` 兜底」 | 方案过时 | 改为 SwiftUI `.quickLookPreview(_:)`（**须同时 `import QuickLook`**）；保留远端文件需先落地的约束 |
| §13.2 分栏视图 | 「`NSBrowser` 的自绘复刻」 | 措辞过时 | 改为「`NSViewRepresentable` 包装 `NSBrowser`」或明确自绘范围 |
| §5 非功能需求 | 内存 ≤150 MB 标注为「WebView 时期基线」 | 基线过时 | 按 Swift 原生重设目标并实测 |
| §0 变更表 #3 / #4 | 理由写在抽象渲染假设上 | 理由过时 | 改为按产品形态与控件层表述（已改） |
| §6.2 / §7 | 含与具体外壳实现绑定的约束 | 部分过时 | 逐条复核，改写为 `macos/` 工程的实际约束 |

### 1.3 产出

- `docs/0926_01_PRD.md` 就地升版为 **v2.1**，新增 §0.1「相对 v2.0 的变更」记录本次改动
- 更新 `README.md` 的「当前状态」表：把「视觉与交互验收 = 未做」细化为指向本方案

### 1.4 验收点

PRD 内不再出现任何作为**实现依据**的抽象渲染约束；所有 UX 章节的约束在 SwiftUI 下可执行。

## 2. Phase 1：交互骨架（P0 — 体感现代化，投入产出比最高）

> **执行状态（2026-10-09）**：1.4 / 1.1 / 1.2 / 1.3 已实现并通过 `swiftc` 编译验证，**运行时行为待人工验收**。剩余已知偏离见 §2.6。

### 2.1 拖拽传输

| 方向 | 行为 |
|---|---|
| Mac 窗格 → 设备窗格 | 上传 |
| 设备窗格 → Mac 窗格 | 下载 |
| Finder → 窗口任意位置 | 上传到设备窗格当前目录 |
| 设备窗格 → Finder | 下载到 Finder 目标位置 |
| 设备窗格内部 | 设备端移动（`mv`，P2） |

要求：拖入时高亮目标区域；多选显示数量徽章；`Android/data`、`Android/obb` 等不可写目录显示禁止光标而非静默失败。

- 实现：`EntryTable` 行加 `.draggable(...)`（`Transferable` / `NSItemProvider`），窗格容器加 `.dropDestination(...)`
- 落地复用现成的 `TransferPlanner.upload` / `.download`，无需新写传输逻辑
- 涉及：`Views/EntryTable.swift`、`Views/MainView.swift`、`App/AppModel.swift`

### 2.2 ⌘C / ⌘V 跨栏传输（PRD §22）

- Mac 栏选中 → ⌘C → 设备栏 ⌘V = 上传；反向 = 下载
- 焦点在文本框（重命名 / 新建文件夹 / 搜索）时恢复文本语义（responder chain）
- 实现：`.onCopyCommand` / `.onPasteCommand` 或 `Edit` 菜单命令 + 焦点判断
- 涉及：`DroidBerthApp.swift`、`Views/MainView.swift`

### 2.3 空格 Quick Look（PRD §23）

- 本地文件：`.quickLookPreview($url)`
- 远端文件：先落到 `$TMPDIR/DroidBerth/preview/` 再预览；> 200 MB 先弹确认
- 涉及：`App/AppModel.swift`、`Support/AppPaths.swift`、`Views/MainView.swift`

> **实现坑（务必记住）**：`.quickLookPreview(_:)` **不在 `SwiftUI` 模块里**，它由
> `QuickLook` + `SwiftUI` 的 cross-import overlay（`_QuickLook_SwiftUI`）提供。
> 只写 `import SwiftUI` 会报 `has no member 'quickLookPreview'`——这正是
> `f4c65d7` 那次「SwiftUI 没有 quickLookPreview」错误结论的根因。正确写法是
> **同时 `import QuickLook`**，之后 `_QuickLook_SwiftUI.framework` 会自动链接。
> 另：该 API 的实际可用性标注是 macOS 11.0+，不是 PRD 写的 14.0+。

### 2.4 窗格聚焦与键盘导航（PRD §22 / §25）

- 焦点态：**系统色描边 + 窗格头加粗**，不能只靠颜色区分（当前仅 `Color.accentColor.opacity(0.06)`，不达标）
- `Tab` 在「Mac 窗格 → 设备窗格 → 传输面板」循环
- `⌘⌥← / ⌘⌥→` 切窗格；`⌘↑` 上级；`⌘[ / ⌘]` 后退/前进；`⌘R` 刷新；`⌘⌫` 删除
- 涉及：`Views/MainView.swift`

### 2.5 验收点

能从 Finder 直接拖文件进窗口完成上传；能把设备文件拖到 Finder 完成下载；⌘C/⌘V 跨栏生效；空格可预览；Tab 可循环聚焦；焦点态有可见描边。

### 2.6 Phase 1 的已知偏离（实现时确定，不是遗漏）

| 偏离 | 说明 | 处置 |
|---|---|---|
| Tab 只做「Mac 窗格 ↔ 设备窗格」两段循环 | PRD §22 要求三段（含传输面板），但面板目前没有键盘可交互的内容，把焦点移进去无意义 | 随 Phase 2.3 传输面板改造补齐 |
| 设备窗格 → Finder 拖出未实现 | 需要 `NSFilePromiseProvider` 支撑「拖到任意位置才决定落点」，与窗格间拖拽是两套机制 | 另立一票，Phase 2 之后 |
| 同侧拖拽（Mac 内部 / 设备内部移动）只给提示 | 需要 move 语义与设备端 `mv` | Phase 4 |
| ⌘X 剪切只给提示 | 同上 | Phase 4 |
| 照片图库不支持空格预览 | 图库条目要先导出成文件 | Phase 3 |
| Quick Look 菜单项**不挂空格快捷键** | 无修饰键的菜单快捷键会先于文本框拿到事件，会把输入框里的空格吃掉。空格只由 `PaneKeyMonitor` 的本地监听处理，它带 `TextEditingRelay.isEditing` 守卫 | 保持现状；菜单项仅提供可发现性与启用态 |
| 多选时按空格不预览 | 面板一次只呈现一个文件，硬挑第一个会造成误解。此时空格交还系统 | 有意为之 |

## 3. Phase 2：工具栏与视觉层（P1）

> **执行状态（2026-10-09）**：3.1 / 3.2（改为位置弹窗）/ 3.3 / 3.4 已实现并通过 `swiftc` 编译与链接验证，**运行时行为待人工验收**。三处刻意偏离见 §3.6。

### 3.1 工具栏重构（PRD §10）

- 左：视图切换分段控件（列表 / 分栏 / 网格），作用于聚焦窗格 —— **延后到 Phase 3**
- 中：`⇄` 交换两侧（**语义已澄清为「交换左右窗格」**，见 PRD §10 的说明）
- 右：搜索框 + `⋯` 溢出菜单；上传 / 下载**保留为常驻按钮**
- 涉及：`Views/MainView.swift`（`toolbar`）、`App/AppModel.swift`、`DroidBerthApp.swift`

### 3.2 位置导航：位置弹窗 + 最近使用（**替代原「可见侧边栏」方案**）

原方案是改用 `NavigationSplitView` 做常驻侧边栏。**评估后放弃**：

- 这是双栏传输工具，第三栏会**永久**吃掉横向空间。窗口最小宽 900pt，减去侧边栏后每栏只剩 ~340pt（当前每栏下限就是 340pt），直接把布局逼到极限
- 「位置」是偶发动作，不值得常驻一栏
- 真正的痛点是**回到上次传的那个项目文件夹**（几百 GB 的素材目录），而不是桌面 / 下载这些固定位置

改为：导航条上的「位置」按钮 → 弹窗，内含**最近使用**（持久化，最多 8 项，可清除）+ 固定位置 + 「其它…」。
- 涉及：`Views/MainView.swift`（`PlacesPopover`）、`App/AppSettings.swift`

### 3.3 传输面板增强（PRD §14）

- 传输速度（MB/s）、剩余时间：数据早已由 `ProgressParser` → `TransferJob` 提供，本次补齐呈现
- 失败行常驻「重试」与「查看原因」（**不藏在 hover 后面**）+ 整行警示色
- 「查看原因」展开后可看完整错误、源 / 目标路径，并可一键拷贝
- 折叠态为单行摘要；有任务时自动展开；可手动固定（pin，持久化）
- 涉及：`Views/TransferPanel.swift`、`Transfer/TransferJob.swift`、`Transfer/TransferQueue.swift`

### 3.4 列表增强（PRD §13.1）

- 列头点击排序（名称 / 种类 / 大小 / 修改日期，升降序），文件夹优先且可在设置里关
- 搜索过滤（作用于聚焦窗格）
- 右键菜单补「新建文件夹」
- 涉及：`Views/EntryTable.swift`、`App/AppModel.swift`、`Support/BrowserEntry.swift`

### 3.5 验收点

工具栏含交换 / 搜索 / 溢出菜单；位置弹窗含最近使用；传输面板显示速度与 ETA、失败可重试且可固定；列头可排序；搜索可用。

### 3.6 Phase 2 的已知偏离与实现要点（实现时确定，不是遗漏）

| 项 | 说明 |
|---|---|
| **视图切换分段控件延后** | 分栏与网格是 Phase 3 内容。先摆一个只有「列表」可用的分段控件属于**假可用**，比没有更糟。⌘1/⌘2/⌘3 一并延后 |
| **上传 / 下载不进 ⋯** | PRD §10 把它们列在 ⋯ 里。这两个是本产品的核心动作，藏进菜单是净损失，保留为常驻按钮（File 菜单 + ⇧⌘U / ⇧⌘S 仍在） |
| **不做常驻侧边栏** | 见 §3.2 的理由。这是对原方案的**主动否决**，不是没做完 |
| **⇄ 的语义按「交换左右窗格」实现** | PRD §10 原文「把两个窗格的位置互换」含混：本地路径与设备路径不可能互相赋值。按双栏管理器的经典语义（交换面板）实现，并在 PRD §10 就地写明 |
| **搜索作用域只在编辑时锁定** | 不跟随焦点实时变化 —— 否则 Tab 一下结果就跳，用户会以为丢了东西。编辑是明确动作，跳变可预期 |
| **换目录清筛选、刷新保留** | 筛选语义是「在当前这个文件夹里找」。换目录后留着旧查询会造成「明明有文件却显示空」 |
| **`Optional` 不是 `Comparable`** | `TableColumn(_:value:)` 要求 `V: Comparable`，Swift 故意不给 `Optional` 定义全序。大小 / 日期列靠 `BrowserEntry.sortableSize` / `sortableModified` 投影成非可空值（未知按 -1 / `.distantPast`，升序时排最前） |
| **列头排序必须自己排** | `Table` 拿到 `sortOrder` 只负责画箭头，**不会重排数据**。`EntryTable` 用单个比较器做「文件夹优先 + 用户列 + 名称兜底」，不依赖 `sorted(by:)` 的稳定性（Swift 未承诺稳定） |
| **名称列要换回本地化比较** | 点击列头时 `Table` 会用**默认比较器**重建 comparator（名称列退化成大小写敏感的字典序，`Zebra` 会排到 `apple` 前）。用一层 `Binding` 包装把它换回 `localizedStandard` |
| **右键「重命名」未做** | 需要设备端 `mv`，属 Phase 4 |
| **⇄ 按视觉位置聚焦** | 交换之后 ⌘⌥← / ⌘⌥→ 必须按**屏幕上的左右**走，不能按 Mac / 设备走，否则反直觉 |

### 4.6 Phase 3.1 的已知偏离与实现要点（实现时确定，不是遗漏）

| 项 | 说明 |
|---|---|
| **工具栏只放「列表 / 网格」两段** | PRD §10 要三段（含分栏）。分栏（§13.2）尚未实现，摆一个按不动的段属于假可用 —— 与 §3.6 拒绝「先摆视图切换控件」同一条判据。⌘2 同样**刻意不挂** |
| **远端取头必须走 `exec-out`，不能走 `shell`** | `adb shell` 的 stdout 走 pty，会把二进制里的 `\n` 翻译成 `\r\n`，图片头当场损坏。设备侧用 `dd` 而非 `head -c`：部分旧 toybox 的 `head` 不支持 `-c` |
| **缩略图不与传输队列共用通道** | 取 64 KB 头不进 `TransferQueue`（否则面板里会留下一堆一次性任务），走独立的 `ThumbnailStore` + 临时目录 |
| **生成尺寸固定 512 px** | 图标上限 240 pt × 2x = 480，512 覆盖所有档位 ⇒ ⌘± 不会触发重新生成 |
| **右键菜单按显式目标动作** | `LazyVGrid` 没有 `contextMenu(forSelectionType:)`，系统不会帮忙选中右键行。照抄列表的「零参闭包 + 读 model 选择」会让右键未选中项去操作上一个选中项 —— 静默做错事。故网格的下载 / 上传 / 删除回调接收目标数组 |
| **网格没有列头排序** | 网格顺序固定为「文件夹优先 + 本地化名称」（图标视图的既有约定）。列头排序是 `EntryTable` 的局部状态，不外溢 |
| **照片图库网格退类型图标** | 图库条目的 `path` 是 `localIdentifier`，缩略图要走 PhotoKit 的 `PHImageManager`。**另立一票**，不塞进本轮 |
| **远端缩略图成品率未验证** | 截断数据能否解码没在真机试过。JPEG 通常可解出部分图像；HEIC / `moov` 在文件尾的 MP4 很可能解不出 ⇒ 回退类型图标。「一律拉完整文件」已被 PRD §23 明确拒绝，因此这一项的真机结论只能等实测 |

### 4.7 Phase 3.2 / 3.3 的已知偏离与实现要点（实现时确定，不是遗漏）

| 项 | 说明 |
|---|---|
| **子项必须异步填** | `NSBrowser` 的 delegate 是同步接口，而设备端列目录要走一次 `adb shell ls` 子进程。delegate 只读缓存，未命中就返回 0 并起异步加载，完了 `reloadColumn` 补行。**本地也走同一条路径**，不搞两套行为 |
| **选择变化没有通知可监听** | `NSBrowser` 只发了「列宽配置变化」的通知（`NSBrowserColumnConfigurationDidChangeNotification`），没有 selection 通知。选中态靠 delegate 的 `selectionIndexesForProposedSelection`（item-based 专用）接 |
| **根 ≠ 当前列目录** | 根是 `localDirectory` / `remoteDirectory`（列表 / 网格显示的目录），当前列目录是 `localColumnDirectory` / `remoteColumnDirectory`。根变了才 `loadColumnZero`；列内点选只更新后者 —— 否则点一下文件夹就整体回到第一列 |
| **路径栏在窗格底部** | PRD §13.2 明文。分栏模式下顶栏**不再**显示面包屑，避免同一信息出现两次；列表 / 网格仍用顶栏 |
| **`ColumnItem` 必须是 class** | `NSBrowser` 会存 item 并靠 `isEqual` / `hash` 判断选中态。Swift 结构体会被装箱成 `__SwiftValue`，比较语义随之失效 |
| **行内图标可能不出现** | `willDisplayCell` 在 item-based 浏览器里是否被调用，Apple 文档没有明确承诺。写上无代价：不调用退化为纯文本行，功能不受影响。**需运行时确认** |
| **照片图库回退成列表** | 图库只有相簿一层，没有目录层级，列视图对它没有意义（`browserChildren` 对 `.photo` 返回空） |
| **「断开连接」只对无线有效** | USB 没有软断开。对 USB 设备给的是明确说明，不是假装做了一件事 |
| **「连接设备…」刻意不摆** | 需要输入 IP / 配对的一套交互，尚未实现。摆一个永远灰着的项是假可用 —— 与「分栏未实现前不挂 ⌘2」同一条判据 |
| **「设备信息」走 banner 而非新面板** | 信息是一次性的；弹窗是一个需要占位的界面承诺（关掉后那块区域还得处理）。真有常驻信息面板的需求再说 |

### 4.8 Phase 3.4（除 VoiceOver）+ Phase 4 的已知偏离与实现要点

| 项 | 说明 |
|---|---|
| **VoiceOver 按要求跳过** | 用户 2026-10-10 明确指示。每行仍无 accessibility label，这是 §8 清单里唯一未打勾的无障碍项 |
| **对比度只做到「部分」** | 承载信息的 `.tertiary` 文字提到 `.secondary`，纯装饰（面包屑分隔符、路径栏图标）保留 `.tertiary`。**没测实际对比度**：系统 `.secondary` 并非按 AA 正文对比度设计，caption 尺寸要严格达标就得放弃系统层级语义色 —— 那会牺牲整个界面的视觉层级，本轮不走这一步 |
| **动态字体只做到「部分」** | 文本一律语义字号、承载文字的定宽改 `minWidth`、网格留白用 `@ScaledMetric`。**没在放大字号下逐屏核对**（本机无法截图） |
| **Reduce Motion 保留淡入淡出** | 位移类动画（交换两侧、banner 滑入、面板展开）退化为无动画；banner 仍保留 `.opacity` —— 淡入淡出不引起前庭不适，完全砍掉反而会让人不知道刚发生了什么 |
| **移动的冲突策略是「整批拒绝」** | 目标目录已有同名 → 一个都不移动并报出冲突名。`mv` 默认静默覆盖，而覆盖的是用户手机上的数据；且设备端没有回收站 |
| **不能移进自身或子目录** | `mv A A/sub` 会把目录搬进自己内部。drop 前显式拦截 |
| **「拖到当前目录」要识别为无操作** | 否则会变成一次假的成功。源目录 == 目标目录的条目先被过滤掉，并给出「已经在…里了」的说明 |
| **⌘X 只对设备端有定义** | Mac 端的移动交给 Finder —— 在双栏工具里给本地文件做剪切会绕过 Finder 的废纸篓语义 |
| **⌘V 的设备端内部路由依赖剪切态** | 普通拷贝的设备端内部粘贴没有定义（`pasteRoute` 只在 `isCut` 时为 `.move`），所以 `PasteRoute` 多了个 `.move` 分支 |
| **重命名后的选中态要跟到新路径** | 否则列表刷新后选中项凭空消失 |
| **改的若是当前目录本身，`remoteDirectory` 与历史都要跟着走** | 否则窗格会停在一个已经不存在的路径上 |
| **`mv` 不加 `-f` / `-n`** | 覆盖与否由调用方先做冲突预检决定，不把「静默覆盖」或「静默跳过」藏在命令开关里 —— 两种静默都比报错更糟 |

### 4.9 Phase 3.5：预览窗格（⇧⌘P）—— 计划外补的一项

PRD §11 一直挂着「显示预览窗格（⇧⌘P）」，但本文档的 Phase 3 没有把它排进去（4.3 只把它列为「仍缺」）。它在 Phase 3.4 / 4 收尾后单独补上。**已实现**（`Views/PreviewPane.swift`）。

| 项 | 说明 |
|---|---|
| **落位：窗口右缘，显示聚焦窗格的选中项** | 双栏工具里若做成「每个窗格各带一个预览栏」，横向空间会被吃掉两次。头部写明来源，免得被当成设备栏的附属 |
| **开关式、默认关** | 与 §3.2 被否掉的**常驻**侧边栏不同 —— 那个是「永远在」，这个是「你可以关」。这正是它能成立的理由 |
| **窗口最小宽随开关切（900 / 1180）** | 预览栏 260pt，没有弹性可言。不抬下限就会把两个窗格压到各自 340pt 以下 |
| **选中预览绝不触发完整下载** | 缩略图只走 `ThumbnailStore` 的 64 KB 文件头通道。完整下载仍只由「空格 Quick Look」和「下载到 Mac」触发 |
| **合计大小不含未知项** | 多选时把「大小未知的条目数」单独说出来。给一个偏小的合计比不给更糟 —— 用户会据此判断这一批有多重 |
| **按来源给一个传输按钮** | 本地 → 上传，远端 → 下载。两个都给只会是噪音；动作直接复用工具栏那两条路径，落点分流与冲突策略因此完全一致 |
| **照片图库的预览退类型图标** | 图库条目不是文件路径，缩略图要走 PhotoKit（同 §4.6） |
| **⚠️ 未验证** | 预览栏的一切运行时行为；缩略图同样带着「截断数据能否解码」的边界 |

**顺带确立的交互规则（重要）**：**在哪个窗格改选择，焦点就落在哪个窗格**（与 Finder 一致）。

此前点选行**不**设焦点，于是「点完设备栏再按 ⌘⌫」会因为菜单项按旧焦点被禁用而**什么都不发生** —— 一个静默的错。预览窗格、⌘C/⌘V、⌘⌫ 都以聚焦窗格为准，这条规则把它们对齐了。同时这一步也修掉了两个既有缺陷：

1. **列视图下 Quick Look / ⌘C / ⌘⌫ / 下载 / 扫描取不到选中项** —— 它们原先都在 `localEntries` / `remoteEntries` 里按 id 反查，而列视图选中的条目可能位于**子目录**，不在当前列表里。现在统一走 `focusedBrowserSelection` / `focusedRemoteEntries` / `focusedLocalURLs`，列视图另记一份选中快照（`rememberColumnSelection`）。
2. 同一份「选中项解析」原先散在七处各写一遍，现在收敛成三个入口。

### 4.10 交互原生化修正（2026-10-10，用户报告 + 主动审查）

用户报告：「按一次空格能弹出预览，但再按一次无法收回」，并要求「尽量使用原生的交互方案，不要脱节」。

**已修**

| 问题 | 根因 | 处置 |
|---|---|---|
| **空格不能收起预览** | ① `.quickLookPreview($binding)` 把面板状态藏在 binding 后面，**面板被关掉后是否写回 nil 没有承诺**；② `PaneKeyMonitor` 是本地监听、优先级高于一切窗口，**空格在到达面板前就被吃掉**（`previewPanel:handleEvent:` 的兜底因此永远调不到） | 按原生做法**自持 `QLPreviewPanel`**（`Support/QuickLookPresenter.swift`），`isVisible` 成为权威状态，空格 = 切换 |
| **模态弹窗弹着时空格切换背后的 Quick Look** | 本地监听不管模态 | `NSApp.modalWindow == nil` 守卫 —— 那一刻空格属于弹窗 |
| **预览面板开着时 Tab 把焦点搬到另一窗格** | 同上，监听无差别接管 | 面板可见时**只保留空格**，其余放行给面板 |
| **面板不跟随选择** | 未做 | 面板开着时改选，内容实时更新（Finder 行为）。**仅本地** —— 远端跟随意味着隐式下载 |

**白拿的原生能力**（自持面板后自然得到）：面板内**方向键在条目间切换**、Esc 关闭、缩放与全屏。

**三处非显然的实现约束**（都踩过，别重犯）：

1. **响应者链**：`makeKeyAndOrderFront` 前必须有人 `acceptsPreviewPanelControl:` 返回 true，否则**面板是空的**。必须挂在 **App 代理**上（响应者链终点）；`.`background` 放的视图是**兄弟节点、不在链上**。
2. 那三个控制方法是 `NSObject` 分类里的 **nonisolated** 方法，覆写后也变 nonisolated ⇒ 碰 MainActor 状态要 `MainActor.assumeIsolated`。
3. `QLPreviewPanelDataSource` / `Delegate` **没标 `NS_SWIFT_UI_ACTOR`** ⇒ @MainActor 的类要 `@preconcurrency` 一致性。

**审查发现但未做**（需取舍，已列入 README「交互层面的已知偏离」）：网格视图无键盘导航 / 方向键 / type-select（**最明显的一处脱节**）、回车重命名、Tab 吃掉系统焦点遍历（产品决策）、Quick Look 缩放动画。

**⚠️ 未验证**：面板能否真的被带出（响应者链那一步本机无法实测）、方向键切换、跟随选择。

## 7. 建议执行顺序

```
Phase 0（PRD 对齐）                                    ✅ 已完成
  └─ Phase 1.4（聚焦态 + 键盘，成本最低，先建立反馈）    ✅ 已完成
       └─ Phase 1.1（拖拽）→ 1.2（⌘C/⌘V）→ 1.3（Quick Look）  ✅ 已完成
            └─ Phase 2（工具栏 + 位置弹窗 + 传输面板 + 列表增强）  ✅ 已完成
                 └─ Phase 3.1（网格视图 + 缩略图）              ✅ 已完成
                      └─ Phase 3.2（分栏视图）+ 3.3（菜单栏补全）    ✅ 已完成
                           └─ Phase 3.4（无障碍，VoiceOver 按要求跳过）  ✅ 部分完成
                                └─ Phase 4（设备端重命名与移动）           ✅ 已完成
                                     └─ Phase 3.5（预览窗格 ⇧⌘P）              ✅ 已完成
                                          └─ PRD 正文里计划要做的事项**至此全部落地**
                                               剩下的只有：无障碍补全（VoiceOver / 对比度 / 动态字体逐屏核对）
                                               以及全部交互的真机运行时验收
```

理由：Phase 1.4 成本最低且能立刻改善「操作有没有被响应」的感知；拖拽是体感提升最大的一项，放其后；网格视图虽重要，但依赖远端缩略图能力，放在 Phase 3 更稳。

**Phase 2 内的实际执行顺序**（按对主场景的价值，而非文档编号）：
3.3 传输面板 → 3.4 列表增强 → 3.1 工具栏 → 3.2 位置弹窗。
理由：传输失败无法重试 / 看不到原因，是主场景（几百 GB 素材推送）最直接的痛点；排序与搜索是素材管理的刚需；工具栏与位置属于整理性质。
